# 转发性能与稳定性修复

本组修复最初以本地补丁形式基于上游提交 `413a125`（v0.1.10）编写，现已并入仓库、随 **v0.1.11** 发布。改动不涉及模型选择、推理档位或工具调用载荷。

## 已确认问题与改动

- 旧的 `res.write()` 循环忽略返回值，慢客户端下不断读取上游。改为 `Readable.fromWeb()` + `pipeline()`，让背压沿转发链传播，取消请求时释放上游。
- 上游读取失败时原来调用 `res.end()`，把截断响应变成正常 HTTP 结束。现在中止响应，让客户端识别传输失败；插件不会自动重放已开始输出的生成请求。
- 流式响应立即发送响应头，加入禁缓存、禁中间层缓冲标记；向网关请求 `Accept-Encoding: identity`，减少压缩层可能造成的分块聚集。上游是否尊重这些设置取决于其实现。
- 原来的认证重试在最终返回前也读掉错误正文。现在只取消即将重试的响应，保留最终 401/403 正文；迟到的 401 复用其他请求已更新的密钥，保留最多一次认证重试。
- 透传 `Retry-After` 与 `x-request-id`，让宿主获得限流等待时间与排查线索。
- 模型清单、密钥兑换和令牌刷新增加 30 秒网络超时；不对整段生成设置 30 秒上限。
- 模型清单轮询不重叠；清单未改变不再广播适配器更新；卸载后不发布迟到结果。

## 验证

`node test/transport.test.mjs`：8 项通过，真实本地 HTTP 客户端访问插件，网关侧使用可控模拟响应。覆盖首块及时到达、UTF-8/工具调用字节完整性、认证错误正文、迟到的并发 401、429 透传、断流、取消、64 MiB 慢消费者、16 路并发。

`node test/catalog-poll.test.mjs`：1 项通过，运行完整 apply 生命周期并模拟宿主与网络边界，验证轮询互斥、无变化不刷新、卸载后不更新。

`node test/card.test.mjs`：70 项原有检查通过。`node --check` 与 `git diff --check` 通过。新增 `npm run test:offline` 可重复运行以上检查，无需登录或消耗模型额度。

本机没有可用的缓存模型密钥，因此没有执行真实生成 A/B 测速，也没有刷新或写入用户凭据。不能据本地模拟结果宣称实际 tokens/s 提升或所有重连已解决。网关排队、上游生成速度、限流和网络中断仍可能影响体验；未关闭宿主的故障恢复机制或伪造 SSE 心跳。
